# 脆弱性検査（2026-10-26）

## 結果

**更新優先度は高い。** 現在の Go 1.27.0 で `govulncheck v1.9.0` を実行すると、標準ライブラリの既知脆弱性 **11 件**が Symbol Results（呼び出し到達あり）として検出された。加えて、ログイン試行記録を無制限に保持するアプリケーション固有の問題を確認した。

今回は検査と報告のみ。アプリケーション、依存バージョン、実行環境は修正していない。実運用への攻撃成功や CVSS は検証していない。

## 対象と方法

対象ソースは HEAD `634af5640d7f9d814981e907c99e80bfbd555d8f`。開始時の `.gitignore` の変更は対象外として保持した。Go サーバー、認証・CSRF・静的ファイル配信・ファイル操作・外部コマンド呼び出し、および Web UI の危険な DOM 操作箇所を重点的に確認した。全行・全機能の監査ではない。

コードグラフを先に参照したが、構築コミットが現在の HEAD と異なったため、指摘の根拠は実ファイルで確認した。FocalSpan は worker timeout により利用できなかった。Codex Security の接続済み環境一覧は空であり、クラウドスキャンは実施していない。

```powershell

# go version go1.27.0 windows/amd64
& 'C:\Program Files\Go\bin\go.exe' run golang.org/x/vuln/cmd/govulncheck@v1.9.0 -show verbose ./...
```

## VULN-20261026-02：未認証ログイン試行の記録が無制限に残る

重大度：**中（サービス拒否リスク）**。場所：`internal/wui/auth.go:253-276`、呼び出し元 `internal/wui/server.go:796-804`。

`allowLoginAttempt` は `remoteAddress + NUL + username` ごとに map エントリーを作る。1 分の期限切れは同じキーのカウンターを初期化するだけで、他の期限切れエントリーを削除しない。削除はログイン成功時の該当キーに限られ、ユーザー名は存在確認より前に記録される。送信元が同じでも、存在しない異なるユーザー名を使えば毎回エントリーが増える。リクエスト本文の 16 KiB 制限とパスワード計算の worker 制限は、記録総数の上限にはならない。

認証 API に接続できる攻撃者は、正しいパスワードなしで記録を蓄積できる。Origin 検査はブラウザからのクロスサイト送信を制限するが、HTTP クライアントからの Origin 指定は防止しない。loopback 限定の配備では攻撃元がローカルに限られ、外部公開されたリバースプロキシ経由では外部から到達し得る。プロキシ側のレート制限があれば影響を軽減できる。実際の OOM 攻撃は行っていない。

限定再現では、実際の `server.allowLoginAttempt` に同一 IP・異なるユーザー名を 1,000 回渡し、記録時刻をすべて 2 分前に設定した。その後、新しいユーザー名を 1 回渡すと map 長は **1,001** となり、期限切れの 1,000 件が残った。監査専用の一時テストで実行し、テストファイルは検査後に削除した。

対処：期限切れ記録を削除し、総件数上限を設ける。ユーザー名単位に加えて送信元単位でも制限し、ユーザー名を変えた記録増殖を防ぐ。修正時は期限切れ削除・上限到達時・同一 IP でユーザー名変更時の回帰テストを追加する。

## 検証と限界

認証、Bearer scope／CSRF、Host ヘッダー、非 loopback リスナー拒否、ログイン前 favicon、再生セッションの不正トークンに関する選択テストは通過。初回は sandbox の一時ファイル rename が Access denied で失敗したため、同じ検証を制限外で再実行して通過を確認した。

```powershell
& 'C:\Program Files\Go\bin\go.exe' test ./internal/wui -run 'Test(RequestOrigin|APIAuth|APITokensAndCSRF|HostHeader|BuildHTTPServersRejectsNonLoopback|FaviconAvailableBeforeLogin|PlaybackRequestSessionRejectsInvalidToken)' -count=1
& 'C:\Program Files\Go\bin\go.exe' test ./internal/auth -count=1
```

UI の変更はなく、ブラウザ／Playwright の実行、稼働中サーバーへの攻撃、実運用設定の読み取り、FFmpeg・SQLite ネイティブ部分・同梱 JavaScript の包括的なアドバイザリ照合、Linux のビルドタグ固有コードのスキャン、全テストは実施していない。既存の `security_best_practices_report.md` の過去の「0 件」は今回の検査結果を示さないため、本報告を新しい検査記録として参照すること。
